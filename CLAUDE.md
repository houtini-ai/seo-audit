# seo-audit-console

**Status:** Working MCP server (v0.1), in active build. Local dir `C:\MCP\seo-audit-mcp`; GitHub `houtini-ai/seo-audit` (private); npm name `@houtini/seo-audit-console`.

**Goal:** one MCP that merges Google Search Console history with site-crawl data (+ DataForSEO) into a deterministic, defensible, *prioritised* technical-SEO audit — replacing the commodity technical-audit deliverable. Consolidates `seo-crawler-mcp` + `better-search-console` (+ later parts of `geo-analyzer`).

> This repo began as a research/planning workspace (see `research/` and `plan/` — still the spec + background). It is now a code repo. The phased research framework in git history is **done**; `research/01–15` and `plan/*` remain the reference.

## The thesis (unchanged)
Collect (crawl + GSC + SERP) → analyse (deterministic checks + the merged GSC×crawl questions) → recommend in priority order with traceable evidence. The differentiator is **honesty about deterministic (D) vs judgement (N)** and **traceability: recommendation → finding → raw datapoint**.

## Architecture (built)
- `src/core/url-key.ts` — the **join key**. GSC `page` and crawl `url` both normalise to `url_key`/`page_key` (force https, unify www/apex per property, strip default ports/fragments/tracking params, sort params, trim trailing slash). Everything joins on it.
- `src/core/AuditDatabase.ts` — one SQLite DB per property: `search_analytics` (GSC), `crawl_metadata`/`pages`/`links`/`errors` (crawl), `url_inspection`, `rank_history`, `audit_runs`/`findings`, `sitemap_urls`, `keyword_intent`/`page_cwv`/`page_entity`/`entity_edge`/`page_backlinks` (on-demand enrichment), `page_snapshots` (change-detection history). WAL + `synchronous=NORMAL` + FKs. **`pages` has a UNIQUE index on `url_key` → only the latest crawl is retained; cross-crawl history lives in `page_snapshots`.**
- `src/core/GscClient.ts` + `GscSync.ts` — GSC API + streamed sync (lifted from better-search-console), writes `page_key`. **Incremental: first sync pulls the window; later syncs resume from `MAX(date) − 3d` (lag buffer) so they're a small delta, not a full re-pull (simracing routine refresh 33min→19s). `fullResync`/`full=true` forces the whole window.** Mode-guard preserves lite vs segmented history (don't wipe on a routine shape mismatch — re-aim to segmented instead).
- `src/core/UrlInspector.ts` — GSC URL Inspection (coverage, google-vs-user canonical, last-crawl) → `url_inspection`.
- `src/core/Crawler.ts` + `extract.ts` + `robots.ts` — **self-contained fetch+cheerio crawler (NOT Crawlee** — Crawlee logs to stdout and corrupts MCP stdio). Async; captures redirect chains; batched writes; robots-polite; adaptive throttling. **Discovery = links + sitemap seeds + GSC-known URLs** (seeded at crawl start, so coverage doesn't depend on the site's sitemap being complete: simracing 29%→70% of GSC URLs; directdrivewheels 102→369 pages). **Redirect/host guard** (`isInternalHost`, shared with the link classifier): a redirect leaving the internal host or hitting a skip-pattern (e.g. Shopify `accounts.*` OAuth) is recorded as a redirect-out on the original URL, never stored as an off-site page (killed 138→0 junk pages on ehi). Skip-list covers search/cart/auth/oauth/login_with_shop/faceted params. Post-crawl: `finalizeLinkGraph` (in-degree + iPR + click_depth).
- `src/core/DataForSeoClient.ts` — Basic-auth client (api.dataforseo.com). **Single-worker serialised** + **20-day SQLite cache**. Location per property. On-demand only.
- `src/core/RankTracker.ts` — DataForSEO `historical_rank_overview` → `rank_history` (the over-time sequence; reconciled with GSC dates in `dashboardData`).
- `src/core/JobManager.ts` — generic detached job registry (return-jobId-then-poll).
- `src/core/Refresh.ts` — orchestrates `gsc → crawl → inspect → ranks` (each skippable).
- `src/audit/checks.ts` + `engine.ts` — **~90 checks** (priority via the 6e yield model: `(T × Y × C) / E` = expected clicks per dev-hour); period-over-period trend checks (GSC history by date): `traffic-decay`, `lost-queries`, `position-slipping`, `rising-pages` (guarded on ≥56-day span); `index-bloat`/`high-ipr-no-traffic` (≥90-day guard); on-page parity: `duplicate-meta-description`, `title-h1-mismatch`, `h1-missing-top-query`; schema: `homepage-missing-org-schema`, `breadcrumb-schema-inconsistent`. `engine.ts` **self-heals the link-graph** (recomputes iPR/click_depth/inlink_count if a crawl left them empty) and **snapshots each crawl** into `page_snapshots` for drift. 6b per-template: `pagination-canonical-to-page-1`, `article-date-illogical`; sitemap reconciliation: `sitemap-non-indexable`, `indexable-not-in-sitemap`, `sitemap-orphan`. Audit aggregates per-page window traffic once + covering indexes (`idx_sa_pk_date`, `idx_sa_q_pk_date`) → ~9× faster on large GSC sites.
- `src/core/sitemap.ts` — XML sitemap fetch/parse (robots `Sitemap:` + /sitemap.xml, sitemapindex, gzip, per-<url> `<lastmod>` capture) → `sitemap_urls` table. **Freshness-honesty (2026-07-20):** `sitemap-lastmod-untrustworthy` (3 tells: >90% same recent stamp / future dates / lastmod claims a change between crawls while every snapshot field is identical) + `no-304-revalidation` (post-crawl probe: 30 most-linked pages with validators get one conditional re-request → `pages.conditional_304`; live-verified — simracing sends Last-Modified yet returns 200).
- `src/audit/templates.ts` — 6b template detection: clusters pages by URL morphology + JSON-LD @type (N≥4, median exemplar); `list_templates` tool. DOM-skeleton LSH refinement deferred.
- `src/audit/opportunities.ts` — 6c new-page engine: GSC demand (rank 11+) − dedup (rank≤10 / page covers ≥70% / contender owns >80%) → lexical clusters scored by impressions × intent, with the nearest existing page to link from; `suggest_pages` tool. Stored-data only (no paid calls).
- `src/core/WikidataClient.ts` + `Entities.ts` — 6d entity layer: heuristic H1→QID resolution via public Wikidata API (45-day cache), `page_entity` + `entity_edge` (P279/P361) tables, `resolve_entities` async tool. Powers `entity-internal-link-gap` (N/judgement — gated behind includeJudgement; H1 resolution can mis-resolve, verify before acting). Plays #2/#3 (entity content-gap, disambiguation footprints) deferred — need page body text / competitor extraction not stored. (schema-validate: invalid-schema, missing-required-fields, schema-value-errors, forbidden-schema; extractor: image-alt, canonical-relative, multiple-canonical, images-missing-dimensions/CLS, heading-hierarchy, mixed-content, meta-nofollow, missing-social-tags; merged crawl×GSC: ghost-pages, title-missing-top-query; link-graph: deep-pages (body-only click depth), underlinked-high-demand (low iPR × high GSC impressions); backlinks: backlinks-to-404, orphan-no-links; **Phase-6a "intent vs reality" (2026-06-21): ipr-bleed-by-status (sum source iPR into non-200 targets), broken-canonical-target, broken-hreflang-target, hreflang-no-return-tag (reciprocation; hrefs resolved+urlKey'd via property host_form), faceted-spider-trap (indexable multi-param, zero GSC impressions), soft-404-shell (URL-Inspection soft-404 + crawl 200); intent-vs-pagetype-mismatch (top GSC query intent vs page schema @type; gated on persisted `keyword_intent`); high-yield-cwv-fail (CWV-failing page that earns clicks; gated on persisted `page_cwv`); plus keyword-cannibalisation tightened to count only pos<20 URLs, exclude pos 1–2 dominance, and (2026-06-24 accuracy fix) require each competing URL to hold ≥10% of the leader's impressions + ≥10 impressions — incidental long-tail appearances were inflating both the URL count and the priority (e.g. "best vr headset" reported 10 URLs when one page held 59,570 impr and nine had 1–7)** — the "expert questions" that need both datasets);
- `keyword_intent` + `page_cwv` tables (6a persistence): `search_intent`/`page_lighthouse` tools write to them when called with `siteUrl`, unlocking the two checks above.
- `src/core/Backlinks.ts` — on-demand DataForSEO backlink profile (summary + per-page counts → `page_backlinks` table) with live HTTP status for 404 detection. **Needs the DataForSEO *Backlinks* subscription** (separate from SERP/Keywords/Labs — a 40204 means it's not activated; surfaced clearly). `pull_backlinks` tool, 20-day cached, on-demand only.
- `src/core/linkGraph.ts` — post-crawl **internal PageRank (iPR, 0–100 log-normalised, nav/footer ×0.2)** + **body-only click_depth** from the homepage + in-degree (`inlink_count`), written to `pages`. **`finalizeLinkGraph()` is the single entry point** (called by the crawler at end-of-crawl AND by `runAudit` as a self-heal). Powers deep-pages, underlinked-high-demand, orphans, ipr-bleed, high-ipr-no-traffic, and the iPR-ranked donor suggestions in `fix_finding`. _Lesson: a killed crawl process leaves these empty (crawl_metadata stuck 'running'); the audit self-heal closes that gap._
- `src/audit/drift.ts` — **change-detection (drift)**: `snapshotCrawl` (field-level SEO snapshot per crawl) + `diffLatest` (severity-classified field diff of the two most recent crawls: status 200→non-200 & noindex-appeared = crit, canonical flip = high, title = med…) + `buildDriftMarkdown`. The `detect_changes` tool is the monitor.
- `src/audit/schema-validate.ts` — local structured-data validator (no schema.org/Google API exists; we don't scrape the undocumented one). Required-field map for **~30 rich-result @types** spanning content, commerce (Product), **jobs** (JobPosting), **datasets** (Dataset), and **travel** (Hotel/LodgingBusiness/Restaurant/TouristAttraction/Trip…). Three mechanisms: hard-required, **ONE_OF** ("at least one of" — e.g. Product offers/review/aggregateRating, JobPosting jobLocation/jobLocationType/applicantLocationRequirements, so remote jobs & review-only products aren't false-flagged), and nested-required (offers→price+priceCurrency, reviewRating→ratingValue, jobLocation→address, only when the parent is present). Value sanity (absolute URLs, ISO-8601 dates, ISO-4217 currency, bare-number price) + type-level dedup. **Required-only by design** — unknown properties/types are NOT flagged (Google ignores them; flagging = false-positive noise). Regression test: `node scripts/probe-schema-rules.mjs` (16 cases incl. the no-false-positive assertions). `extract.ts` is HTTP-only (no JS render — that's the deferred render tier, #7). _(Findings are scored by the 6e model `(T × Y × C) / E` above, not the old severity×log formula.)_
- `src/core/dashboardData.ts` — builds the dashboard payload (summary, rank trend, distribution, striking-distance, page-performance categorised, keyword movement, device/country, rank history + GSC↔DFS date reconciliation, latest findings). **Plus `templateMismatch` (iPR% vs traffic% per template) + `equityScatter` (per-URL iPR×impressions, bucketed) for the "equity vs reality" charts, an `impact` (0–100, normalised to run max) + `size` (S/M/L/XL) on each finding — shown instead of the raw priority float / clicks "forecast" (Gemini consult) — and `topLinkedPages` (most-internally-linked URLs + live status; a non-200 high up = equity leak).**
- `src/ui/` — MCP-App dashboard (ext-apps + houtini `tokens.css` + **ECharts**, Vite single-file). Findings treemap + ranked table + 6 charts + report tables + CSV export.
- `src/server.ts` / `index.ts` — `McpServer`, stdio, `SERVER_VERSION` derived from `package.json`.

## Conventions (hard rules — learned the hard way)
- ES modules, `.js` extensions in imports. Node ≥ 20.
- **Never `console.log`** — MCP speaks JSON-RPC over stdio; use `console.error` for debug.
- **`SERVER_VERSION` is derived from `package.json` at runtime** — never hardcode (it drifted before). Keep `server.json` version in sync with `package.json`.
- **No Crawlee** (stdio corruption); the crawler is hand-rolled and stdio-safe.
- **Long ops are async jobs** (crawl, sync, inspect, ranks) — never block the MCP tool call past the ~60s ceiling. Return a jobId; poll `check_sync_status`/`check_crawl_status`.
- **DataForSEO: never bulk.** Per-keyword data is on-demand (click/explicit list); one `historical_rank_overview` per refresh. 20-day cache; location per property (`"Australia"`, `"United Kingdom"`, code). Our client calls the API directly — `ENABLED_MODULES` only gates the *official* DataForSEO MCP, not us.
- **Secrets** live in `.secrets/` (gitignored) — also `.claude/`, `*.db`, `gsc-access-*.json`, `.env`. Never commit secret values; read creds from env.
- **D/N honesty:** every finding labels D (deterministic, cite bytes) or N (judgement, gated behind `includeJudgement`).
- Owned-site crawling only; polite (≤ a few rps, respect robots, identifiable UA).

## Build / run
- `npm run build` = `build:server` (tsc → `dist/`) + `build:ui` (Vite single-file → `dist/src/ui/dashboard.html`).
- Probes (outside the MCP): `npm run probe:crawl <url>`, `npm run probe:gsc <property> <url>` — diff live API responses vs what we store.
- Env: `GOOGLE_APPLICATION_CREDENTIALS` (required), `SAC_DATA_DIR` (optional), `DATAFORSEO_USERNAME`/`PASSWORD`, `DATAFORSEO_CACHE_DAYS`. Tools degrade gracefully when a credential is absent.
- Data dir resolution: `SAC_DATA_DIR` env > persisted choice (`~/.seo-audit-console.json`, set via the `data_location` tool) > **`~/Documents/seo-audit-console`** default. Crawls/GSC always fetch fresh (no-cache); the only cache is DataForSEO (20-day, non-page data).
- **Registered in Claude Desktop** (runs the local build: `node C:\MCP\seo-audit-mcp\dist\index.js`). Testing local changes = `npm run build` + full restart of Claude Desktop (quit from tray). The live MCP server holds the *previous* build until restart — local probe scripts (`node scripts/run-ehi-audit.mjs`) exercise fresh code against the synced DB without a restart.
- **Diagnostics learned this build:** verify the data pipeline both statically (schema columns ↔ writes ↔ reads) and dynamically (per-column populated-% on a real DB surfaces silent write-gaps — that's how the iPR no-op was caught). `pages.robots` empty on Shopify sites is legitimate (no meta robots), not a bug. GSC `coverage_state`/`page_fetch_state` come back human-readable ("Submitted and indexed", "Soft 404"), so the substring LIKEs are correct.
- **Correctness pass (2026-07-17, 3-agent review):** destructive wipes are now DEFERRED to first successful write (crawler `ensureWiped` for pages/links; GSC shape-conflict wipe rides in the first batch's transaction) so a failed crawl/sync can't destroy the previous snapshot. Sitemap `<loc>` is XML-entity-decoded (querystring URLs never matched url_keys before). robots.txt now applies only the most-specific UA group (RFC 9309 — a bot-specific group REPLACES `*`, never merges). Cannibalisation's `positions` range ("1.1–15.3") is priced at its midpoint, not parseFloat's best-position. `fix_finding` redirects use the crawler's RECORDED destination (fuzzy match only for true 404s); htaccess/nginx rules are exact-match + regex-escaped. `agentReadiness` validates body shape (a catch-all-200 SPA scored ~100 before). `detect_changes` normalises the two `captured_at` formats before ordering (ISO vs SQLite made baselines invert). Trend-check `spanDays` measures to `gscMaxDate`, not raw MAX(date); duplicate link rows from multi-URL redirects are deduped via an `emitted` set; GSC seeding fetches the raw `page` URL, not the normalised key.

## Tools (current)
`refresh_property` (sync everything; `segments` opt-in for device/country) · `sync_gsc` · `start_crawl` · `inspect_urls` · `track_ranks` · `check_sync_status` · `check_crawl_status` · `list_properties` · `run_audit` · `query_audit` · `fix_finding` (finding→fix moat) · `list_checks` · `seo_audit_help` (overview + example prompts) · `data_location` (get/set data dir) · `keyword_volume` · `related_terms` · `pull_backlinks` (DataForSEO; needs Backlinks subscription) · `search_intent` (Labs; intent classification) · `page_lighthouse` (On-Page; lab CWV) · `competitors_domain` (Labs) · `page_intersection` (Labs; content gap) · `normalize_url` · `detect_changes` (drift/change-detection) · `list_templates` · `suggest_pages` · `resolve_entities` · `get_dashboard` (App UI) · `get_dashboard_data` (app-only) · `export_report` (shareable HTML).

**MCP App large-data pattern (important):** a host caps the *model-facing* tool result ("exceeds maximum allowed tokens" at ~60k chars). So `get_dashboard` returns only `{siteUrl}` + a short summary, and the widget fetches its full (~73k) dataset itself via `app.callServerTool('get_dashboard_data')` — an app-only tool (`_meta.ui.visibility:['app']`) whose result routes to the iframe, bypassing the model token cap (confirmed via ext-apps docs + Gemini). This is why an oversized `get_dashboard` previously failed to render while BSC's small one did. `sync-progress` uses the same callServerTool pattern.
